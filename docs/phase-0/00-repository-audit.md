# 00 — Repository Audit

**Purpose:** identify, from the actual code, what to **preserve, migrate, rewrite, deprecate, or remove** before any implementation begins. Grounded in a full read of the local project source and the GitHub clone, plus the team's own docs (North Star, HANDOFF, Build Plan v2).

---

## 1. The two-codebases problem (resolve this first)

There are two distinct implementations of "The Missing Peace," and they are on different stacks.

### A. Local working project — `C:\Users\siddi\Documents\The Missing Peace`
This is the **real product** and the recommended source of truth.

- **Stack (matches the directive exactly):** Next.js 15 App Router, React 19, TypeScript, Tailwind 3.4, Clerk (`@clerk/nextjs` 6), Supabase (`@supabase/ssr` + `supabase-js`), Liveblocks (client/node/react 2.20), Anthropic SDK, Resend, Svix, Zod, Zustand, tldraw + react-moveable (board canvas), OpenNext for Cloudflare, Wrangler.
- **Depth:** ~55 `.ts` + 45 `.tsx` files, 13 SQL migrations defining **60 tables**, 7 vitest suites (**27 tests reported green**), full app shell, ~18 app routes, a public guest-site surface, a printables pipeline, and a working Peace Engine.
- **Deployment:** scaffolded for Cloudflare Workers via OpenNext (`wrangler.jsonc`, `open-next.config.ts`), plus a separate Pages build for the prototype.
- Note: HANDOFF.md refers to the folder as `C:\Users\siddi\Documents\TMP`; the connected folder is `...\The Missing Peace`. Confirm which path is canonical (see Risk R-12).

### B. GitHub repo — `github.com/kiddsiid/themissingpeace` (Emergent-scaffolded)
This is a **divergent second implementation** on a **non-target stack**, generated by the Emergent platform (`.emergent/emergent.yml`, job created 2026-07-13).

- **`backend/`** — Python **FastAPI** + **MongoDB (motor/pymongo)** + `emergentintegrations`, `slowapi`, `uvicorn`. This is a completely different persistence and server model from Supabase/Postgres.
- **`frontend/`** — **Create-React-App** (`react-scripts`) + React Router + Radix + axios. Not Next.js. Contains pages the local app does **not** yet have: `FeastStudio.jsx`, `AtmosphereLab.jsx`, `CatererBrief.jsx`, `WebsiteStudio.jsx`, plus `Compass`, `Studio`, `Guests`, `MoneyMap`, `Timeline`, `Vendors`, `Playlist`, `Pricing`, `PublicSite`, `AuthCallback`, and feast components (`FeastMap`, `PeacePanel`, `DishEditor`, `DishCard`).
- **`_reference_nextjs/`** — a **snapshot of the local Next.js project** carried inside the GitHub repo as "reference." It mirrors codebase A closely and is what this audit read from directly.
- Auth here is **Emergent Google Auth** (`auth.emergentagent.com`), not Clerk — see `auth_testing.md`.

### Verdict on the split
The directive says "treat the existing stack as the preferred foundation unless the audit proves a change is necessary," and names the *local* project's stack. Therefore:

- **Codebase A (local Next.js) = source of truth. Keep and build on it.**
- **Codebase B backend (FastAPI/Mongo) = deprecate/remove.** It duplicates the engine on a stack the directive does not want, with a second auth system and a second database. Keeping it alive guarantees drift and doubles the security surface.
- **Codebase B frontend (CRA) = mine for concepts, then remove.** Feast Studio, Atmosphere Lab, and Caterer Brief are real product surfaces the directive requires and the local app lacks. Port them as **new Next.js modules against the canonical schema**, using the CRA versions only as design/interaction references. Do not run the CRA app in production.
- **`_reference_nextjs/` = redundant.** Once codebase A is the single repo of record, delete this embedded copy to end the "which is real?" confusion.

**Action A-0 (blocking, Phase 1 start):** pick one repository of record, push the local Next.js project to it, archive the Emergent scaffold on a clearly-labeled branch/tag, and stop editing two trees.

These are the crown jewels the North Star calls the moat. They are built, tested, and on-stack.

This is the spine of "one canonical wedding state."
- **The deterministic rule pack** — `src/lib/engine/rules.ts`. Pure, unit-tested functions for budget overage, missing core vendors, overdue tasks, decision bottlenecks, per-guest math. Exactly the "use deterministic logic for facts" the directive demands. Keep.

Benchmarked ranges, fit readings, Compass-protecting tradeoffs, "never exact promises" tone. This is advisory-planning infrastructure exactly as the directive scopes it. Keep.

- **Seating geometry** — `src/lib/seating/layout.ts` (pure seat math, 11 tests) and the Seating Studio. North Star flagship. Keep.
- **Board → Poof → Master Vision** conversion surface — `src/lib/poof.ts`, `board/*`, `MasterVision.tsx`, smart tagging (`board/tags.ts`), mood extraction (`engine/mood.ts`). The "inspiration becomes decisions/vendors/budget" edge. Keep.

## 3. Migrate — valuable but needs to move or be re-homed

- **Feast Studio, Atmosphere Lab, Caterer Brief** — exist only in the Emergent CRA `frontend/` and/or prototype HTML. Migrate as **new Next.js App Router modules** against the canonical schema (needs new tables — see data model §"Additions"). Use the CRA/HTML as interaction reference only.
- **Atelier (attire)** — exists as a directive requirement and prototype concept, not as code in either tree. Net-new build on the shared model.
- **Prototype content & copy** — the enchanted language, section intros, and imagery treatment in `prototype/*.html` should migrate into the real design system and the cinematic public site, but the **standalone HTML/JS must not migrate as an app** (see rewrite).
- **The Emergent `frontend/lib` presence/dreamPool concepts** — re-express through the existing Liveblocks setup (`src/lib/liveblocks.ts`), not the axios/CRA versions.

## 4. Rewrite — keep the intent, replace the implementation

- **The public prototype** — currently ~15 standalone `.html` files + `wedding-state.js`/`support.js`/`mobile.js` persisting to **`localStorage`** and deployed as a separate Cloudflare Pages site. Directive non-negotiables #5/#21 require this to become **demo mode of the real components via a demo adapter**, clearly distinguishing seeded vs. real data. Rewrite as: (a) the cinematic marketing story, and (b) a seeded demo that renders the *actual* React modules with fixture data. Retire the standalone HTML app.
- **Weaver/Peacekeeper AI surface** — `engine/peacekeeper.ts` is a single server call that returns strict JSON. It must grow into the bounded **Weaver** service the directive specifies: citations to supporting records, confidence/uncertainty, approve/dismiss/edit/defer, an audit trail, and per-surface **loading/empty/failed/stale/retry/preserved-edit** states. Model id is currently hard-coded (`claude-sonnet-4-6`) — move to config. Keep the deterministic/AI split; expand the contract.
- **Dream Walk** — `onboarding/*` + `dream/DreamWorkspace.tsx` exist but the directive's "Dream Walk Redesign" (one-question-at-a-time journey, live world response, gravity, earned Compass reveal, plain-English language rules) is a substantial rework, not a tweak. Rewrite the flow; keep the Compass persistence and Dream Clouds visual.
- **RLS enforcement path** — migrations 0002 (GUC) and 0003 (Clerk JWT) coexist; HANDOFF confirms the GUC approach does **not** hold over PostgREST and the app relies on **service-layer scoping** today. Rewrite to a single proven Clerk-JWT RLS path and add an automated unauthorized-access test (directive requires "test unauthorized access explicitly").

## 5. Deprecate — stop investing, remove after migration

- **Emergent `backend/` (FastAPI + MongoDB).** Deprecate immediately; remove once nothing references it.
- **Emergent `frontend/` (CRA).** Deprecate after Feast/Atmosphere/Caterer concepts are ported.
- **Emergent Google Auth** (`auth.emergentagent.com`, `auth_testing.md`). Superseded by Clerk. Remove.
- **`_reference_nextjs/` embedded copy** and the many `tmp/claude-prototype-*` working folders — build cruft; remove.

## 6. Remove — dead weight / hazards

- **Committed build artifacts & archives:** `.next/`, `.open-next/`, `.wrangler/`, `_deploy/themissingpeace-pages.zip` (5.3 MB), `The Missing Peace.zip` (5 MB), `tsconfig.tsbuildinfo`, `cloudflare-env.d.ts` (0.5 MB generated). Ensure `.gitignore` covers them and they are not tracked.
- **Secrets hazard:** `.env.local` is present in the local folder and **must never be committed**. `.env.example` is the correct tracked template. Verify `.env.local` is git-ignored and rotate any key that has ever been pushed (see Risk R-1).
- **Duplicate deploy configs:** `cloudflare-page/`, `cloudflare-pages/`, `cloudflare-prototype/` overlap. Consolidate to one product target + one demo target.

## 7. Test & verification state (as found)

- **Unit tests:** 7 vitest suites — `compass`, `rules`, `money-map`, `seating`, `guest-page`, `link-preview`, `board-vision`. HANDOFF reports **27/27 green**. This is real but **narrow**: it covers pure engine/geometry/util logic. There are **no** integration tests, **no** RLS/authorization tests, **no** component/E2E tests, and **no** accessibility or performance tests — all of which the directive's Definition of Done requires evidence for.
- **Build/type:** HANDOFF reports TypeScript and production build passing at last checkpoint.
- **Live DB:** last recorded count was **empty** (0 users/workspaces/…). The engine has not been exercised against real multi-tenant data at volume.

## 8. Audit conclusions (the through-line)

1. The product is **much further along than "a prototype,"** and on the right stack. The correct posture is **preserve-and-harden**, not rebuild.
2. The **single biggest structural risk is the two-codebase split.** It must be closed before Phase 1 work, or every later phase pays a drift tax.
3. The **three functional gaps** that matter most against the directive are: the **creative modules** (Feast/Atmosphere/Atelier), the **bounded/auditable Weaver**, and the **couple-vs-planner two-experience split**. Everything else is depth on an existing base.
4. The **two safety gaps** that must not reach launch are **proven RLS** and a **truthful prototype/demo** (no fake persistence, no fabricated social proof).
